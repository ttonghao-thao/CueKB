# 验收与评测方法

更新：2026-10-26。本文定义如何验证；本轮实际执行结果仅在[任务板](../TASK_BOARD.md)维护。这里不预填预期Recall或P95为已达成。

## 1. V2完整验证

所有现存CueKB接口与处理链均为V2，验证包含检索、导入、知识库、Key、Job、发布、模型、generation及健康检查。

```sh
make test
make check
make check-contracts
node --check src/cuekb/portal/app.js
sh -n scripts/deploy-production.sh
```

`make test`执行当前完整测试集；记录passed、failed、skipped及原因。门户渲染用例需要Node.js，缺失时的跳过不算前端通过。契约检查核对现有导出物，不能通过无解释地重新生成来清除失败。

| 验证层 | 能证明什么 | 必须另外验证的内容 |
| --- | --- | --- |
| V2算法、DTO与内存HTTP | 归属边界、有限召回/选择、真实评分规则、精确预算、响应及并发状态隔离 | 真实模型召回/重排质量、数据库和搜索引擎行为 |
| 超时与取消 | 冷首次请求、慢鉴权/配置依赖和已进入的异步检索均受同一入口deadline；截止后不启动后续检索，取消后请求任务收尾 | 真实PG驱动连接回收、远端服务是否停止计算 |
| 模型/OS MockTransport | 请求/响应协议、部分分片失败识别、索引映射与绑定校验 | 真实BM25/k-NN召回、服务故障和负载 |
| 门户实际JS函数 | 主事实、必要上下文、转义与缺失提示的渲染规则 | 真实浏览器交互及外部客户端证据裁剪 |
| 专用PG | 当前schema、处理快照、发布和事务取消等真实SQL行为 | OS一致性、模型质量及目标环境稳定性 |

真实PG测试只指向**专用测试库**，设置`CUEKB_TEST_DATABASE_URL`后执行`make test`，其中数据库用例会使用该专库。fixture创建独立随机schema并直接加载完整初始化结构，结束后drop该schema，必要时创建public.pgcrypto，不得指向业务库。未配置时跳过，不算通过真实PG验收。

数据库与全新部署共用完整`db/schema.sql`，需核验不可变快照/幂等、source_version同文档FK、恢复新ID、旧清理不误删新块、发布删除/撤权竞争、pg_sleep超时取消与连接回收。OS需核验V2映射、实际BM25/k-NN、过滤投影及索引写后校验。尚无现成用例或本轮未执行的场景列入任务板，不因方法写在本文就算已覆盖。

## 2. 固定验收数据

使用英文通识、两种以上产品及技术手册，固定原件hash、版本/processing_profile、PG内容修订、模型不可变revision、dimension、generation、运行代码和配置。相同权限、相同query/filter/top_k做前后对照，保留冷/热状态。

人工标注每题必要证据单元，允许多个等价chunk；标注产品归属、型号参数、单位/比例、适用/限制条件、否定、例外、重复、冲突及无答案。不把模型输出当唯一gold。文档变化后chunk ID会改变，必须重新绑定标注，不能跨版本直接计算旧gold。

至少包括：单片段；跨块/章节/文档；型号与技术参数；多条件例外；未知/歧义归属；无匹配与低相关；冲突；更新/删除/撤权；必要依赖超预算；未配及已配Reranker。两种月饼等业务样例由获授权数据提供，不能在产品代码硬编码。

## 3. 指标口径

| 指标 | 计算与限制 |
| --- | --- |
| Recall@K | K为最终hit上限；hit与其合法context_parts形成返回证据组，命中gold必要单元数/必要单元总数；等价ID不重复计数 |
| MRR | 第一条命中任意gold单元的hit组名次倒数；有gold但失败/空结果计0 |
| 证据完整率 | 所有必要单元同时返回；gold_plans可声明多个OR替代方案，每个方案unit_ids为AND；context_state=unresolved组不计完整覆盖，不等于系统自动充分性判定 |
| 无答案效果 | 人工无答案集统计not_found正确识别、误有答案、错误/降级；高分不作为充分性标签 |
| 归属与事实保持 | 人工检查产品/版本、表头、数值、单位、比例、否定及限定条件，无误归属或编造 |
| 延迟与稳定性 | 所有请求（含错误）P50/P95/P99、HTTP错误/超时、吞吐、资源占用；同时检查并发质量变化 |
| 负载 | 返回hits精确bytes、正文及context大小、省略原因；语音模型实际注入token另测 |
| 动态选择 | 同预算下实际返回precision、平均条数/字节、Recall与完整率，停止原因及校准状态；不能仅靠多返回内容宣称改进 |

验收阈值应在目标语料和业务风险下确认；当前没有经过实测的通用通过阈值。相关性校准先按独立family划分calibration/test，拟合方法见[操作手册](OPERATIONS.md#7-相关性校准配置)。对比ranked、adaptive无校准及adaptive已校准，并分别跑无Reranker/有Reranker；逐项消融词法字段、预算替补、覆盖选择和门控。单元测试只验证算法规则，未校准不能保证低相关即空结果。冲突证据可以并列返回，系统不自动裁决新旧或真伪。

## 4. 可执行验收与评测工具

### 4.1 专用实例功能验收

`scripts/acceptance-production.py`使用V2上传、文档详情和检索；健康、Key、授权、Job、发布及原件下载同样使用`/v2`管理路径。它会创建专用测试KB、文档和业务Key，成功时删除自己的文档与Key；失败或中断后可能需要清理残留。当前没有删除KB接口，成功结束后也会留下空测试KB。只能指向允许这些写入的专用实例。

先在安全环境设置`CUEKB_BOOTSTRAP_API_KEY`，无需把密钥值放在命令行：

```sh
.venv/bin/python scripts/acceptance-production.py \
  --url https://cuekb-test.example.internal
```

需先按操作手册配置Embedding并启动Worker、PG和OS；可用`--expect-rerank`要求真实执行重排。该脚本通过不代表质量或并发达标；隔离Mock协议回归也不能记作真实实例验收。

### 4.2 只读质量与10并发评测

`scripts/evaluate-retrieval.py`只调用V2检索，不写数据。输入JSONL，每行：

```json
{"sample_id":"voltage","request":{"query":"Input voltage","kb_ids":["11111111-1111-4111-8111-111111111111"],"mode":"hybrid","top_k":8},"gold_evidence":[{"unit_id":"voltage-with-condition","chunk_ids":["55555555-5555-4555-8555-555555555555"]}],"forbidden_chunk_ids":[],"expected_status":"ok"}
```

chunk_ids是一个单元的OR等价ID列表；事实、必要条件分别列为AND单元，不能把它们误填为等价项。可选gold_plans形如`[{"unit_ids":["fact","condition"],"document_ids":["来源文档UUID"]},{"unit_ids":["complete-alternative"]}]`，方案之间OR，方案内AND。未提供时所有gold单元均必需。完整率排除unresolved上下文，普通Recall仍统计实际返回ID；不能把一个孤立高分块算成完整证据。

无答案题设置answerable=false、空gold及expected_status=not_found；有答案题设置answerable=true，分别计算误收和空返率。forbidden_chunk_ids可标记过期、错误产品或撤权证据；未标负例需人工检查。gold不能通过同名产品无版本地匹配。precision_returned采用与离线关联实验相同的最大匹配口径，重复等价单元不会多得分；一组含多个必要单元时完整率与precision口径需分别理解。

在安全环境设置`CUEKB_TEST_API_KEY`为专用read Key后：

```sh
.venv/bin/python scripts/evaluate-retrieval.py \
  --url https://cuekb.example.internal \
  --cases /secure/frozen-cases.jsonl \
  --output /tmp/cuekb-evaluation \
  --concurrency 10 --repeat 20 --timeout 10
```

结果summary.json含Recall/MRR/完整率、expected status计数、错误与延迟；requests.jsonl含sample_id、trace、修订、诊断，不输出完整证据或query。工具保留HTTP/transport错误对质量的0分影响，百分位用nearest-rank并包含所有请求。concurrency是闭环最多同时10请求，非10 QPS；延迟从dispatch开始，不含调度前队列，需另做目标到达率/饱和压测才能评估排队效应。少量样本的P99不能当稳定容量结论。

分别跑无Reranker和有Reranker，检查实际executed_stages、ranking_method及backend_calls，不只看配置开关。记录总请求数、运行时长、语料块数、目标主机CPU/GPU/内存、模型服务、网络和超时。固定query不代表每次排序完全确定，外部模型可变修订要注明。

### 4.3 用户Monkey月饼语料复验

`scripts/validate-monkey-corpus.py`固定用户TXT的SHA256，运行当前test_choice_review与test_choice_transports。原件不入库分发。专用本地PG/OS必须为loopback，测试创建/删除独立schema/index；输出目录必须不存在。运行需dev、api依赖；实际DOCX解析另需ingestion依赖及CPU Torch。缺少依赖产生skip，脚本将skip判为未完整通过。

```sh
CUEKB_TEST_DATABASE_URL=postgresql+psycopg://cuekb@127.0.0.1:5432/cuekb_test \
  .venv/bin/python scripts/validate-monkey-corpus.py \
  --input /secure/Monkey-Brand-Mooncake.txt \
  --opensearch-url http://127.0.0.1:9200 \
  --output /tmp/cuekb-monkey-validation
```

覆盖A100/A200/套件隔离、型号边界、编号TXT与多产品表格列、真实DOCX、审核原子性/修订/ACL、草稿与应用幂等、跨页集合/部分进度/修订冲突、Setext及数值列表、拆分覆盖/撤回、排除必要条件、模板快照及目录批量回滚、解析进程时限。真实PG+OS+HTTP查询验证exact/hybrid/adaptive及Embedding故障后的BM25路径，检查主事实和全部context_parts。模型使用本机8维固定向量夹具，只验证真实协议/过滤，不作语义质量结论。

月饼用例基于内容检查，不依赖旧ordinal 47：单品100g/42元/45天与混合礼盒分开，鲜肉产品过滤不得带入蛋黄规格。为聚焦该回归，未被规则确认的其他材料被明确排除于新派生版本，原始草稿保留；这不表示整份语料已通过业务精度验收。完整语料仍需人工标注主体、限定与相关性，加入多个产品家族并隔离开发/验收文档。自动确认覆盖率与误归属率分别报告，不以Recall高替代污染检查。

输出pytest.log、results.xml、summary.json，包含原件hash/处理修订/范围/通过与skip计数。测试日志可能包含片段，保留在受控目录，不自动提交。新脚本替代旧修订按段落ordinal映射的验证方式；历史665管线通过及业务失败记录用Git追溯，不视为当前质量结论。真实模型、跨语言、复杂PDF/OCR及生产并发性能仍按独立验收执行。

## 5. 端到端独立验收

CueKB验收只证明本次返回的原文证据。voice-service-agent必须独立升级严格DTO和引用映射，保留必要依赖、按预算取证，验证复合问题逐项回答、比例口述、否定/例外表达及实际播放。调用方裁剪后遗漏条件不能由CueKB的top_k或未裁剪响应承担保证。

## 6. 门户原文与上下文验收

先运行`make test`与`node --check src/cuekb/portal/app.js`。选定的门户回归执行实际app.js函数，覆盖V2长主事实、必要条件、同身份去重、HTML转义和未解决依赖。

浏览器在独立测试实例按以下场景复测，并与同一HTTP响应对照；不要将受控候选结果当作模型质量基准：

1. 具备重复介绍和多个属性的样例，adaptive应保留属性证据且不从可选近邻重新注入已排除介绍；比较ranked与adaptive条数、停止原因及实际正文。
2. 必要条件不单独占主结果名额，显示“命中原文”和真实依赖正文；同一主块不在上下文中重复展示。
3. 主事实长于上下文预算时，source_text仍完整显示；如果context只容纳条件，也不能覆盖主事实，并保留预算提示。
4. 必要依赖缺失显示unresolved提示；正常not_found空结果与请求错误分别表达，充分性保持unassessed。
5. 在V2的ranked/adaptive间切换；ranked不携带动态专用输入，原文与必要上下文保持可见。最后关闭测试标签页和隔离服务。

归属审核回归见tests/test_scope_review.py、tests/test_scope_review_postgres.py和门户Node用例。真实浏览器需覆盖：待办候选、产品/通用资料/必要关系选择、多产品事实/表格列隔离、跨页冻结集合与进度、重处理新版本、服务端发布阻塞及正常发布。验证新版本ready期间原发布指针不变，发布后新事实/来源生效，恢复后再次重处理仍能定位当前源单元。

安全与失败场景包括：缺少/未匹配/冲突的归属原因；未知条件通过可信直接关系补入而不改变产品身份；普通unknown近邻、跨产品/版本、伪造来源、删除后依赖均排除；重复同名章节不猜测、数字章节号不截断、缺失引用显式unresolved、超过20依赖不报完整。人工未匹配定位/环应使任务确定失败，不因重试变为成功。审核接口验证write权限、版本归属、分页及汇总，不能泄露完整实体快照。

## 7. 重构阶段交付与用户部署验证

本节约定后续每批交付的执行闭环，不表示尚未实现的验证脚本已经可用。实施阶段为S0–S6；缺口F01–F12及其优先级在重构设计维护。

### 7.1 交付前由开发者准备

每次交付必须提供以下完整内容，不能只写“请部署验证”：

1. **交付范围和身份**：阶段/子任务、关联缺口、两个仓库各自提交号、修改了哪些服务、前置阶段状态。明确代码完成、开发验证通过、待部署验证三种状态。
2. **部署步骤**：在实际部署方式下可复制的命令；注明宿主机或哪个容器执行、工作目录、配置位置；明确是否重建API/Worker/VoiceChat、迁移、重处理原件、重新发布或重建generation。操作应保留旧环境和数据，附回退条件与命令。不能让用户自行猜测需不需要删卷或重导入。
3. **身份检查**：自动采集运行提交/镜像digest、schema revision、generation、模型/tokenizer、必要的挂载文件hash。版本不符则停止验收并提示具体差异，不混入新版本报告。
4. **固定用例**：提供输入文件/问题/音频及校验hash、执行顺序、预置条件、预期字段/行为和通过标准。合成数据标为合成；私有语料不提交公开仓库。性能与真实模型测试明确硬件、并发、次数、持续时间与采样方法。
5. **执行与采集**：提供已经检查可运行的验证入口及完整命令，自动关联session/input_revision/trace，自动统计结果并导出脱敏报告。依赖不存在时明确失败，不输出伪通过。命令不得含密钥，日志不回显凭据；产品API验证尽量在部署容器运行，宿主机仅作启动/汇总入口。
6. **判定与回传**：明确退出码、输出目录/文件名、哪些内容原样回传以及失败如何采集。预期至少含机器可读汇总、逐用例结果、必要时间线与环境身份。不能只给成功路径，或要求用户自行挑日志/诊断根因。

若一批功能还不具备可执行验证入口，应先补齐入口再交付；不能用本文的规则代替具体命令。涉及voice-service-agent/VoiceChat的操作与采集以该仓库docs/validation.md为唯一执行手册，交付时更新对应提交并提供准确章节，避免维护两份不一致的现场命令。

### 7.2 各阶段怎样验证、取得什么证据

| 阶段 | 部署后执行内容 | 自动采集/用户补充 | 判定 |
| --- | --- | --- | --- |
| S0 联合基线 | 检查运行身份；通过真实消费者发起固定知识查询，再执行冻结语音样本 | 请求/响应契约结果、trace与input关联、实际选中来源、准确注入token数及阶段时序；用户确认是否实际听到正式答案 | 契约不拒绝；版本匹配；性能基线完整。此阶段测量基线，不要求提前达到S5优化目标 |
| S1 文档核心 | 导入指定TXT/DOCX/PDF、产品表格及非产品制度；运行升级/回退测试 | 文档树/节点与原件定位、表头脚注关系、schema与generation、任务状态及升级前后数据核对 | 与结构金标匹配；原文/权限不丢失；非产品资料无需绑定产品；回退可恢复 |
| S2 异常审核 | 按固定页面步骤检查A100/12V、A200/24V候选；选择、批量确认、撤回、排除条件及发布 | 候选与问题ID、决定审计、修订冲突、发布资格；自动操作计数与时长，用户补充实际操作是否清楚 | 明确内容自动通过；歧义可选择；必要条件排除阻塞依赖事实；旧发布版不被草稿覆盖 |
| S3 证据引擎 | 固定金标题批量查询，覆盖多属性、无答案、歧义、冲突、预算不足、权限/版本变化及依赖故障 | 逐题决策、facet/引用/条件、拒答原因、相关性/覆盖指标和阶段耗时；缺金标的题单列 | 按本文件及重构设计第12章指标；不因返回200或top5齐全就通过 |
| S4 消费集成 | 经真实工具通道提问，覆盖一次可答、澄清、缺项、重复调用、修订与取消 | 实际模型收到的脱敏视图、主张引用、工具企图与实际执行次数、输入修订、最终回答 | 不遗漏已问属性；补查符合状态机；技术失败不冒充无答案；不混入其他产品条件 |
| S5 语音性能 | 用固定音频及20/100/300/500token包，在真实GPU执行规定重复次数/并发；覆盖注入期间讲话 | 原生注入/排队/首正式音频/浏览器播放时序、丢帧/修订计数、分位数及错误率；用户实际听音记录 | 质量与性能同时满足；ACK不算正式答案；缺实测项标证据不足，不用模拟填充 |
| S6 上线替换 | 执行影子对比、受控切换、撤销权限与删除传播、备份恢复及回滚 | 两版本差异、发布矩阵、切换事件、恢复后数据与权限核对、残留旧路径检查 | 切换与恢复符合预期；无权限泄漏/混版本；旧路径按计划退出 |

阶段用例的文件、命令、样本量与阈值必须随对应实现落地后填实。表中的测量任务不是要求用户自建数据集、编写脚本或选择技术方案；开发者负责准备，业务金标有歧义时给候选与依据供用户确认。

### 7.3 用户回传与结果处理

用户每次回传验证入口生成的摘要及约定报告；补充实际听音、页面行为和执行中看到的错误即可。建议摘要包含：交付批次、执行时间/时区、运行版本、报告路径、脚本退出码、成功/失败/跳过数量、用户观察。不要回传.env、API Key或未经脱敏的整库内容。

开发者检查报告完整性后逐项标记：通过、失败、证据不足或不适用（需说明原因）。失败定位到代码/部署/数据/模型后给出修复及针对性重测步骤；证据不足时只补采缺失边界，不默认整套重测。禁止把跳过、未运行或样本量不足算通过。

任务状态统一为：待开发→开发中→代码完成/开发验证通过→已交付待用户部署→用户已部署待验证→验证通过（或失败/证据不足）。推送成功不是阶段完成；代码修复后需根据影响重新取得验证结论。用户回传前可继续无依赖的开发准备，但不能宣称依赖现场结果的阶段已经验收、擅自上线切换或替用户执行生产部署。

### 7.4 门户目录刷新与失败跨页操作修复的部署验证

本批只改门户脚本，无schema/Worker/解析策略变更。沿用现有数据库、索引及审核草稿，不需重导原件或重建generation。宿主机在CueKB仓库目录执行（以下使用默认镜像标签；自定义CUEKB_API_IMAGE时构建为该实际标签）：

```bash
git pull --ff-only origin main
docker build --target api -t cuekb-api:latest .
docker compose --env-file .env.production up -d --no-build --no-deps --force-recreate api
docker compose --env-file .env.production ps api
```

重新打开门户标签页，避免继续使用已加载的旧脚本。操作者在测试知识库使用admin权限，保留生产审核决定。验证并回传下表结果：

| 用例 | 页面操作 | 预期/回传 |
| --- | --- | --- |
| 创建产品 | 在审核弹窗新建一个单品，不关闭弹窗，展开跨页指定产品 | 单条和跨页两个下拉框均出现新产品；回传产品名称、两个位置可选/不可选 |
| CSV导入 | 导入另一个目录项，原弹窗查看两个下拉框 | 两处都立即出现，不需刷新页面；回传导入结果 |
| 套件校验 | 在测试草稿选择包含套件与普通内容的范围，尝试绑定单品 | 拒绝错误绑定，中文说明单品与组合装需分开，保留trace；回传错误原文、审核计数，不要强行改产品类型 |
| 更换操作 | 上一步422后改为“暂缓处理”，重新预览，在测试草稿确认 | 预览明确显示新操作；Network中apply请求action为defer，不重复旧assign；暂缓仍阻塞发布，不算审核通过 |
| 正确分组 | 对真实业务内容按适用产品分别确认；套件选真实bundle | 无非法套件绑定；品牌历史可通用，单品规格不混入其他产品；回传阻塞数变化及无法处理片段 |

管理员可用浏览器Network保留失败/重试的路径、状态码、请求action及trace，不回传Authorization头、Cookie或.env。开发者结合这些结果判断：目录刷新两处一致、422后可以改变操作、错误产品绑定继续拒绝三项都成立才算本批现场通过。本地Node执行的是实际脚本加模拟DOM/API，不替代真实浏览器/数据库验证。

### 7.5 S1文档核心与门户本批部署验收

本批交付：核对S0契约及采集入口，交付S1代码及三项门户操作；S0尚缺的真实语音时序基线仍需按调用方验证手册回传。涉及schema与API/Worker，按[操作手册第8节](OPERATIONS.md#8-s1保留数据升级验证与回退)保留数据升级，两种应用镜像都须重建。先保存运行镜像并备份，执行upgrade/check，再启动；没有旧schema的自动破坏性转换，不删卷，不需要为本批更换Embedding或重建generation。

**容器内格式/发布验证**：在门户选择一个可写的测试知识库，复制完整UUID（避免与业务知识混杂）。下列宿主命令通过API容器执行真实上传、Worker解析、结构检查及发布，默认覆盖TXT/Markdown/DOCX/PDF；会留下名为S1 validation的合成文档便于查看。将命令中的UUID替换为该测试KB UUID；--bootstrap使用API容器已有系统管理Key，不打印凭据。

```bash
docker compose --env-file .env.production exec -T api cuekb-db check
docker compose --env-file .env.production exec -T api cuekb-validate-s1 --bootstrap --kb-id TEST_KB_UUID --output /tmp/cuekb-s1-report.json
docker compose --env-file .env.production cp api:/tmp/cuekb-s1-report.json ./cuekb-s1-report.json
docker compose --env-file .env.production images api worker
```

验证入口最后输出报告路径、passed/failed，全部格式通过退出0，否则退出1。失败也生成报告，仍执行cp回传；不要把未运行、失败或改为只测TXT解释为全部格式通过。每格式等待有界（默认600秒，可通过--wait-seconds缩短/延长到最多1800），不触发HTTP自动重试；实际任务仍受Worker超时/重试限制。报告含原件hash、文档/版本/任务ID、工作阶段与错误码、树revision/status/节点类型、范围阻塞、发布结果、数据库revision/checksum（若可采集），不含Key或业务原文。PDF/OCR资源不可用时回传报告，由开发者诊断；不是用户自行更换模型或绕过失败。容器重建会丢失/tmp报告，请先复制到宿主机。

**门户验证**：重新打开门户标签页，完成下表并回传实际结果。使用测试文档与真实目录，不为了通过将套件绑定单品。

| 项目 | 操作 | 通过标准/回传内容 |
| --- | --- | --- |
| 删除同步 | 导入测试文档，看到导入状态卡片后，从文档详情删除该文档，回到导入页 | 关联全部版本卡片消失，等待5秒不重现；其他文档卡片保留。回传删除前后卡片数量及是否重现 |
| 审核子页 | 分别从导入状态、文档详情进入审核，再进高级配置后返回，使用页面返回与浏览器后退 | 审核没有模态遮罩；返回原操作入口；回到审核时页码/筛选/滚动与未变更的勾选保留。回传入口、实际URL及异常 |
| 勾选批量 | 第一页选1条、第二页选1条，仅对这2条“暂缓处理”；再选择其他记录做正确的产品/通用确认 | 只改变勾选项；成功清空勾选；暂缓仍阻塞发布；未选项计数不变。回传前后计数及操作 |
| 校验拒绝 | 在测试草稿勾选套件与单品，尝试统一绑定单品，然后调整勾选后重试 | 错误批次整批不写入，保留勾选与中文错误；调整后可提交正确操作，不跳过错误片段冒充成功 |
| 原件结构 | 检查验证器创建的制度文档；旧版本缺树时点“按当前结构重新解析原件” | 新树保留章节/表格/脚注（输入有时），非产品资料无需逐片段绑定产品；新版本发布前旧发布版仍可查询 |

**需要回传**：cuekb-s1-report.json、两应用运行镜像信息、上述5项结果；出错时附错误原文/trace和相关任务ID即可。不回传.env、Authorization、Cookie或私有整库内容。开发者根据报告分别记录代码/部署/格式/门户通过、失败或证据不足；发布质量与语音SLO仍由后续S2–S6验收，本批不以功能测试宣称Nano时延已达标。


### 7.6 分类审核、原草稿发布与校准故障修复验收

部署步骤和schema要求以[操作手册第8节](OPERATIONS.md#8-s1保留数据升级验证与回退)为准。本批升级后刷新门户，使用隔离测试知识库验证以下项目；不对生产文档作故障注入。

| 场景 | 操作与通过标准 |
| --- | --- |
| 多产品共同说明 | 对确实共同适用的片段勾选两个产品并确认；保存后解除该项阻塞，原文与必要条件仍保留 |
| 同名目录身份 | 同一原文名称命中多个身份时显示“目录身份重叠”，可核对型号/编号后选一个确认，不强制拆分相同文字 |
| 不同规格 | 分别赋值的规格不能整体共同归属；页面给出拆分/暂缓提示，不再提供必然失败的统一绑定入口 |
| 暂缓与排除 | 暂缓保持阻塞；不纳入检索保留原件及审计，若被其他事实依赖仍不能直接发布；最后一项完成后准备按钮立即可用 |
| 原草稿发布 | 记录document_id/version_id及版本数，完成审核准备索引后在本页发布；ID与版本数不变，排除段不进入检索，已发布版本只读；失败重试仍使用同一任务/版本 |
| 校准故障 | 测试环境配置无效校准文件，exact/hybrid及ranked/adaptive请求仍返回HTTP 200与relevance_profile_invalid诊断；原有ACL和最终可见性检查不放宽；恢复有效匹配文件后检查校准状态 |

回传应用提交/镜像、schema check输出、版本前后ID和数量、审核/任务结果及查询trace即可，不回传校准文件中的私有数据或凭据。真实OpenSearch、模型与原始业务文档的成功结果，才计入现场验收。
